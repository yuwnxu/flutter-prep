## Яндекс.Метрика (AppMetrica)

Нужны: API-ключ (его выдадут организаторы или создадите в кабинете), пакет `appmetrica_plugin`.

```dart
Future<void> main() async {
  WidgetsFlutterBinding.ensureInitialized();
  await AppMetrica.activate(const AppMetricaConfig('API_KEY'));
  runApp(const MyApp());
}
```

События в игре Image: **каждое движение** и **отправка** результата.

```dart
class Analytics {
  static void imageMove(int moveNumber) =>
      AppMetrica.reportEventWithMap('image_move', {'move': moveNumber});

  static void imageSubmit(int seconds, int moves) =>
      AppMetrica.reportEventWithMap('image_submit', {'seconds': seconds, 'moves': moves});
}

// в контроллере игры
void swap(int a, int b) {
  ...
  Analytics.imageMove(moves);
}
```

::: warn
API плагина и версии меняются: сверьтесь с README `appmetrica_plugin` и инструкцией для Android/iOS. Событие должно улететь в метрику **до** презентации — данные появляются в кабинете с задержкой.
:::

Сделайте пару прогонов игры, затем в кабинете откройте отчёт по событиям и сделайте **скриншот диаграммы**.

### Сборка APK с подписью

```bash
keytool -genkey -v -keystore upload-keystore.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload
```

`android/key.properties` (**не коммитьте!**):

```
storePassword=...
keyPassword=...
keyAlias=upload
storeFile=../upload-keystore.jks
```

В `android/app/build.gradle` подключите `signingConfigs` и используйте их в `release`. Затем:

```bash
flutter build apk --release
```

Файл лежит в `build/app/outputs/flutter-apk/app-release.apk`.

### Иконка и название

- Иконка приложения: пакет `flutter_launcher_icons` или замена файлов в `mipmap-*`.
- Название приложения: `android:label` в `AndroidManifest.xml` и `CFBundleDisplayName` в `Info.plist`.
- Идентификатор: `applicationId` (Android) и `Bundle Identifier` (iOS), например `ru.example.combats`.

## Подробно: ответы на вопросы комиссии

Принцип: **коротко, по делу, с примером из кода**. Если не знаете, скажите честно «не успела реализовать, но сделала бы так: ...».

| Вопрос | Основа ответа |
|---|---|
| Почему три слоя? | Изменение экрана не затрагивает бизнес-логику и данные; проще тестировать |
| Зачем интерфейс репозитория? | Domain не зависит от реализации, можно заменить источник данных |
| Чем DTO отличается от Entity? | DTO — формат сервера, Entity — модель приложения; изменение API не ломает экраны |
| Как вы сделали одинаковую картинку? | Генератор случайных чисел с seed из id игры |
| Почему отдельная сетевая библиотека? | Независимое версионирование, заменяемость, тесты |
| Что в вашем коде нарушает SOLID? | Назовите конкретное место и как исправили бы |
| Как приложение работает без интернета? | `NoInternetException`, SnackBar на 5 секунд, кэш картинок |
| Что бы вы улучшили? | Конкретные пункты: тесты UI, локальная БД, обработка гонок |

## Подробно: производительность — что и как измерять

1. Запустите приложение в режиме профилирования: `flutter run --profile` на реальном устройстве.
2. Откройте **DevTools → Performance**, нажмите запись, пройдите сценарий «собрать пазл Image».
3. Найдите кадры, которые вышли за 16 мс (красные столбцы): это «рывки».
4. Улучшите: `const` конструкторы, `RepaintBoundary` вокруг плиток, вынос неизменяемых виджетов, кэш картинок, `ListView.builder`.
5. Замерьте ещё раз и сохраните скриншоты «до» и «после».

Для слайда достаточно: «в сценарии Image средний кадр X мс; после оптимизации Y мс; что сделал».

## Подробно: публикация в RuStore пошагово

1. Создайте аккаунт разработчика в RuStore Консоли (организаторы дадут доступ или инструкцию).
2. Создайте приложение, укажите **название** (как в задании) и **тип** (приложение/игра).
3. Загрузите **APK** (подписанный release-сборкой).
4. Загрузите **иконку** (по требованиям консоли: обычно квадрат PNG).
5. Выберите **категорию** и **возрастную категорию** (0+, 6+, ...).
6. Заполните **краткое** и **полное описание**.
7. Загрузите минимум **5 скриншотов**.
8. Проверьте и сохраните черновик; отправлять на модерацию, если не сказано, не нужно.

Тексты описаний готовьте заранее в файле, чтобы на соревновании только вставить.

Пример краткого описания (до 80 символов, уточните лимит): «Соревнуйтесь в пазлах Image и Circle и следите за статистикой».

Пример основного описания:

```
Игровое приложение для двух соперников. Создавайте игры по расписанию,
находите соперника, собирайте пазлы Image (картинка) и Circle (круги)
на скорость и смотрите статистику побед. Приложение напомнит о начале
игры за час. Фото профиля можно выбрать из галереи или сделать на камеру.
```
