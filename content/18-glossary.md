## Процесс и организация

| Термин | Что значит |
|---|---|
| Спринт | Короткий отрезок работы с набором задач и ограниченным временем |
| Таск-трекер | Сервис с карточками задач (как Trello, Jira, YouTrack) |
| Канбан-доска | Доска с колонками этапов задачи: «К разработке» → «В работе» → «К тестированию» → «Завершена» |
| Инвариант | Обязательная часть задания для всех регионов |
| Вариатив | Часть задания, которую выбирает регион |
| Аспект | Один пункт оценивания в таблице критериев |
| Измеримый («И») | Аспект с ответом «есть/нет» |
| Судейский («С») | Аспект с экспертной оценкой 0–3 |
| Эксперт | Человек, который проверяет вашу работу |
| Главный эксперт (ГЭ) | Руководитель проверки, согласует пакеты и правила |
| Менеджер компетенции | Автор конкурсного задания |
| Инфраструктурный лист (ИЛ) | Список оборудования и программ на площадке |

## Git

| Термин | Что значит |
|---|---|
| Репозиторий | Папка проекта с историей изменений |
| Коммит | «Снимок» проекта с описанием; имеет уникальный хэш |
| Хэш коммита | Длинный код вроде `5899748`, по нему находят нужную версию |
| Ветка (branch) | Отдельная линия изменений, не мешающая `main` |
| `main` | Основная ветка проекта |
| Merge | Слияние одной ветки в другую |
| Pull request (PR) | Запрос на слияние ветки: его просматривают, а потом принимают |
| Push / Pull | Отправить изменения на сервер / получить с сервера |
| Тег | Метка на коммите, например `v1.0.0` |
| Semver | Система версий МАЖОР.МИНОР.ПАТЧ |
| `.gitignore` | Список файлов, которые Git не должен хранить |

## Dart и Flutter

| Термин | Что значит |
|---|---|
| Dart | Язык программирования, на котором пишут Flutter |
| Flutter | Фреймворк для мобильных приложений от Google |
| Виджет | Любой элемент интерфейса: кнопка, текст, отступ, экран |
| Stateless | Виджет без изменяемого состояния |
| Stateful | Виджет с состоянием, которое меняется |
| State | Объект, где хранится состояние Stateful-виджета |
| `setState` | Команда «перерисуй виджет с новыми данными» |
| `build` | Метод, который описывает, как выглядит виджет |
| `BuildContext` | «Адрес» виджета в дереве, нужен для темы, навигации, размеров |
| Hot reload | Мгновенное применение изменений без перезапуска |
| `pubspec.yaml` | Файл настроек проекта: пакеты, шрифты, ресурсы |
| Пакет (package) | Готовая библиотека кода с pub.dev |
| `async` / `await` | Ключевые слова для работы с долгими операциями |
| Future | Результат, который появится позже |
| Stream | Поток значений во времени |
| Null safety | Защита от пустых значений: обычные типы не могут быть `null` |
| Mixin | Набор методов, подмешиваемый в класс |
| Extension | Добавление методов существующему типу |
| Sealed class | Класс с ограниченным набором наследников, удобен для состояний |
| Generics | Обобщения: `List<int>`, `Box<T>` |
| Scaffold | Каркас экрана: AppBar, body, drawer, bottomBar |
| Sliver | Элемент прокручиваемой области (`CustomScrollView`) |
| Constraints | Ограничения размера, которые родитель передаёт ребёнку |
| Navigator | Управляет стеком экранов |
| Drawer | Выдвижное боковое меню |
| BottomSheet | Панель, выезжающая снизу |
| SnackBar | Всплывающее сообщение внизу экрана |
| `mounted` | Признак, что виджет ещё на экране |
| Lifecycle | Жизненный цикл: создание, использование, удаление |

## Архитектура

| Термин | Что значит |
|---|---|
| Архитектура | Способ разделения кода на части с чёткими обязанностями |
| Domain | Слой бизнес-правил, не знает ни о UI, ни о сети |
| Presentation | Слой экранов и управления их состоянием |
| Data | Слой получения данных: API, БД, хранилище |
| Entity | Чистая модель предметной области (Game, Player) |
| DTO | Модель данных «как пришло с сервера», может отличаться от Entity |
| Mapper | Преобразователь одной модели в другую |
| UseCase | Одно действие пользователя в виде класса (`CreateGame`) |
| Repository | Посредник, который отдаёт данные слою Domain |
| Data source | Источник данных: удалённый (API) или локальный (память) |
| DI | Внедрение зависимостей: объект получает нужные ему части снаружи |
| Абстракция | Интерфейс, который описывает «что делать», а не «как» |
| SOLID | Пять принципов проектирования (S, O, L, I, D) |
| DRY | «Не повторяйся»: одна логика живёт в одном месте |
| SRP | Одна ответственность на класс |
| Контроллер / ViewModel / Bloc | Объект, который управляет состоянием экрана |

## Сеть

| Термин | Что значит |
|---|---|
| Клиент | Ваше мобильное приложение |
| Сервер | Компьютер, хранящий данные и отвечающий на запросы |
| API | Набор адресов и правил общения с сервером |
| REST | Стиль API: запросы HTTP, данные в JSON |
| HTTP-метод | GET (получить), POST (создать), PUT (изменить), DELETE (удалить) |
| Эндпоинт | Конкретный адрес запроса, например `/games` |
| Заголовок (header) | Служебная информация запроса, например токен |
| Токен | Строка, которая подтверждает, что вы вошли |
| Статус-код | Результат: 200 успех, 400 плохой запрос, 401 нет доступа, 404 не найдено, 500 ошибка сервера |
| JSON | Текстовый формат данных `{"id": 1}` |
| Сериализация | Объект → строка JSON |
| Десериализация | Строка JSON → объект |
| Таймаут | Максимальное время ожидания ответа |
| Мок (mock) | Заглушка вместо настоящего сервера в тестах |
| Интерсептор | Перехватчик запросов/ответов (общая обработка ошибок, токена) |

|---|---|
| UIKit (в задании) | Отдельная библиотека компонентов интерфейса |
| StoryBook | Приложение-витрина со всеми компонентами |

| Токены дизайна | Именованные значения: цвета, размеры, радиусы |
| Макет | Дизайн в Figma |
| Dev Mode | Режим Figma для разработчиков с размерами и стилями |

| Состояния компонента | default, focused, disabled, error, pressed и т. д. |
| Auto layout (Figma) | Автораскладка, аналог Row/Column |

## Хранение и устройство

| Термин | Что значит |
|---|---|
| SharedPreferences | Простое хранилище пар «ключ — значение» |
| Secure storage | Защищённое хранилище для токенов |
| Кэш | Локальная копия данных, чтобы не загружать их повторно |
| Сессия | Состояние «пользователь вошёл» |
| Разрешение (permission) | Согласие пользователя на доступ к камере, уведомлениям |
| Локальное уведомление | Уведомление, созданное приложением без сервера |
| Манифест | Файл Android с настройками и правами приложения |
| `Info.plist` | Аналогичный файл настроек для iOS |

## Тестирование и публикация

| Термин | Что значит |
|---|---|
| Unit-тест | Проверка отдельной функции или класса |
| Тест-кейс | Описание: предусловия, шаги, ожидаемый результат |
| Mock-сервер | Имитация сервера для тестов |
| `expect` | Проверка результата в тесте |
| Метрика (AppMetrica) | Сервис аналитики: какие действия делают пользователи |
| RuStore | Российский магазин приложений |
| APK / AAB | Файл сборки Android-приложения |
| Keystore | Файл-ключ для подписи приложения |
| Возрастная категория | Рейтинг 0+, 6+, 12+, 16+, 18+ |
