## Почему это важно

В таблице критериев почти у каждого пункта методика: **«половина итоговой оценки, если отсутствуют комментарии и логирование согласно заданию»**. То есть идеальная верстка без комментариев и логов даёт 50%.

## Что комментировать

**Для каждого класса верхнего уровня** (виджет, контроллер, репозиторий): краткое описание, дата создания в формате `ДД-ММ-ГГГГ` и автор (номер участника).

```dart
// Репозиторий для работы с API игр.
// Отвечает только за получение и отправку данных об играх (SRP).
// Дата создания: 11-11-2026
// Автор создания: 7
class GameRepositoryImpl implements GameRepository { ... }
```

::: warn
В вашей симуляции даты записаны как `15.10.2026`, а в задании требуется `ДД-ММ-ГГГГ`, то есть **`15-10-2026`**. Мелочь, но это один из пунктов проверки.
:::

**Публичные методы:** что делает, что принимает, что возвращает (кроме тривиальных геттеров/сеттеров).

```dart
// Создаёт новую игру на сервере.
// Принимает: название [title] и время начала [startAt].
// Возвращает: созданную игру [Game].
Future<Game> createGame({required String title, required DateTime startAt}) async { ... }
```

**Сложные алгоритмы (больше 5 строк):** строчные комментарии внутри метода к условиям, циклам и вычислениям.

```dart
bool isSolved(List<int> order) {
  // Идём по списку и проверяем, что каждый элемент на своём месте
  for (var i = 0; i < order.length; i++) {
    if (order[i] != i) return false; // нашли неправильный — пазл не собран
  }
  return true;
}
```

## Логирование: уровни

| Уровень | Для чего | Пример |
|---|---|---|
| **DEBUG** | Технические данные для отладки | Содержимое ответа, результат вычисления |
| **INFO** | Ключевые события | `initState`, запрос отправлен, пользователь вошёл |
| **ERROR** | Сбои и исключения | Таймаут, код 500, пойманное исключение |

## Обязательные точки логирования

1. **Жизненный цикл экранов** — уровень INFO (`initState`, `dispose`, `AppLifecycleState`).
2. **Сетевые запросы и БД** — начало (INFO), успех (DEBUG), ошибка с типом (ERROR).
3. **Нажатия на критические кнопки** («Отправить форму», «Начать игру») — INFO.
4. **Любой `try-catch`** — запись ERROR с сообщением исключения.

## Формат сообщения

```
[Тег_компонента]: Событие — Детали
[AuthController]: Авторизация — Успех для пользователя user@mail.com
[ApiRepository]: Ошибка — Не удалось получить список игр (код 500)
```

## Готовая обёртка над `logger`

```dart
import 'package:logger/logger.dart';

// Единая точка логирования приложения.
// Дата создания: 11-11-2026
// Автор создания: 7
class AppLog {
  static final Logger _log = Logger(printer: SimplePrinter());

  // Формирует сообщение по формату задания: [Тег]: Событие — Детали
  static String _fmt(String tag, String event, String details) => '[$tag]: $event — $details';

  static void debug(String tag, String event, String details) => _log.d(_fmt(tag, event, details));
  static void info(String tag, String event, String details) => _log.i(_fmt(tag, event, details));
  static void error(String tag, String event, String details, [Object? err, StackTrace? st]) =>
      _log.e(_fmt(tag, event, details), error: err, stackTrace: st);
}
```

Использование:

```dart
Future<void> _onLoginTap() async {
  AppLog.info('LoginScreen', 'Нажатие', 'Кнопка «Войти»');
  try {
    AppLog.info('AuthController', 'Запрос', 'POST /login отправлен');
    final user = await _login(email, password);
    AppLog.debug('AuthController', 'Ответ', 'userId=${user.id}');
  } catch (e, st) {
    AppLog.error('AuthController', 'Ошибка', 'Вход не выполнен', e, st);
  }
}
```

## Типичные ошибки

| Ошибка | Исправление |
|---|---|
| Формат с дефисом вместо тире | Используйте `—` как в задании |
| Логи только в `initState` кнопки, а не в сетевых вызовах | Добавьте три точки логов на каждый запрос |
| `catch` без лога | В каждый `catch` добавить `AppLog.error` |
| Комментарии только на английском/смесь | Выберите один язык и держитесь его |
| Лог на каждом `build` | Шумит; логируйте события, а не перерисовку |

## Что нужно уметь

- Написать шапку класса и описание метода по шаблону.
- Подключить `logger` и использовать формат задания.
- Расставить 4 обязательные точки логирования.

## Подробно: шапки для разных типов файлов

| Тип файла | Что написать в шапке |
|---|---|
| Экран (`*_screen.dart`) | «Экран <название>: <что показывает и какие действия доступны>» |
| Контроллер | «Контроллер экрана <название>: управляет состоянием и вызывает <UseCase>» |
| UseCase | «Сценарий <действие>: <правило>, вызывает <репозиторий>» |
| Репозиторий (интерфейс) | «Контракт получения/отправки <данных>» |
| Репозиторий (реализация) | «Реализация <Контракта>: берёт данные из <источника>, преобразует в Entity» |
| DTO | «Модель ответа сервера для <запроса>» |
| Mapper | «Преобразование <DTO> в <Entity> и обратно» |
| Виджет-компонент | «Компонент <название>: <что отображает>, состояния: ...» |
| Файл цветов/типографики | «Единый источник цветов/текстовых стилей приложения» |
| `main.dart` | «Точка входа: инициализация зависимостей и запуск приложения» |

Все шапки содержат ещё и **дату `ДД-ММ-ГГГГ` и номер участника**. Настройте в Android Studio **Live Template**, чтобы шапка вставлялась одной командой (Settings → Editor → Live Templates → Dart).

## Подробно: где ставить логи — таблица по слоям

| Место | Уровень | Пример |
|---|---|---|
| `initState` экрана | INFO | `[LoginScreen]: Жизненный цикл — initState` |
| `dispose` экрана | INFO | `[LoginScreen]: Жизненный цикл — dispose` |
| `didChangeAppLifecycleState` | INFO | `[GameScreen]: Жизненный цикл — paused` |
| Нажатие критической кнопки | INFO | `[LoginScreen]: Нажатие — «Войти»` |
| Начало запроса | INFO | `[HttpApiClient]: Запрос — POST /auth/login` |
| Успешный ответ | DEBUG | `[HttpApiClient]: Ответ — 200 /auth/login` |
| Ошибка сети | ERROR | `[HttpApiClient]: Ошибка — Нет интернета: /games` |
| Работа с хранилищем (чтение/запись) | INFO / DEBUG / ERROR | `[SessionStorage]: Чтение — token найден` |
| `catch` | ERROR | Всегда, с сообщением исключения |
| Результат игры отправлен | INFO | `[ImageGame]: Результат — время 00:42` |

**Что считается «критической» кнопкой:** отправка формы, начало игры, публикация игры, выход, подключение к игре, выбор фото. Остальные («назад», «показать пароль») логировать не обязательно, но можно.

## Подробно: как в команде договариваются о стиле комментариев

На соревновании вы одна, но эксперту должно быть видно единообразие:

- Один язык (русский) во всех комментариях.
- Одинаковая структура шапки.
- Комментарий отвечает на вопрос **«зачем»**, а не пересказывает код.

Плохо и хорошо:

```dart
// плохо: пересказ
i++; // увеличиваем i на 1

// хорошо: смысл
moves++; // считаем ход для статистики и метрики
```

## Практика: автопроверка комментариев и логов

Скрипт, который находит файлы без шапки и места без логов:

```bash
# файлы без шапки
grep -rL "Автор создания" lib --include=*.dart

# catch без AppLog.error рядом (грубая проверка)
grep -rn -A3 "catch" lib --include=*.dart | grep -L "AppLog.error" || true

# забытые print
grep -rn "print(" lib --include=*.dart

# файлы с неверным форматом даты (точки вместо дефисов)
grep -rnE "Дата создания: [0-9]{2}\.[0-9]{2}\.[0-9]{4}" lib
```

Запускайте проверку **за 10 минут до конца каждого спринта**. Для тренировки:

1. Добавьте шапки во все файлы своего UIKit.
2. Замените Logging на AppLog с форматом из задания.
3. Проверьте, что в каждом `try-catch` есть запись ERROR.
