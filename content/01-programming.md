## Программа и алгоритм

**Алгоритм** — конечная последовательность шагов, которая решает задачу. **Программа** — алгоритм, записанный на языке, который понимает компьютер. Мобильное приложение — большая программа, которая реагирует на касания, запрашивает данные у сервера и рисует экран.

Пример алгоритма «проверить пароль»:

1. Получить введённую строку.
2. Если её длина меньше 8 — показать ошибку и остановиться.
3. Иначе отправить пароль на сервер.

## Основные кирпичики

| Понятие | Что это | Пример на Dart |
|---|---|---|
| Переменная | Именованная ячейка памяти | `int score = 5;` |
| Тип данных | Какие значения допустимы | `int`, `double`, `String`, `bool` |
| Условие | Выбор ветки выполнения | `if (score > 3) { ... }` |
| Цикл | Повтор действий | `for (var i = 0; i < 3; i++) { ... }` |
| Функция | Именованный кусок кода, который можно вызвать | `int sum(int a, int b) => a + b;` |
| Коллекция | Много значений вместе | `List<int>`, `Map<String, int>` |
| Класс | Шаблон для объектов с данными и поведением | `class Player { ... }` |

## Как язык превращается в приложение

1. Вы пишете **исходный код** (`.dart`).
2. Компилятор превращает его в машинный код (Android — ARM, iOS — ARM) либо запускает в режиме отладки на виртуальной машине Dart (**hot reload** работает именно так).
3. Приложение запускается на устройстве и общается с системой: рисует экран, получает касания, обращается к камере и сети.

## Клиент и сервер

- **Клиент** — ваше мобильное приложение.
- **Сервер** — компьютер в интернете, который хранит данные (пользователи, игры).
- **API** — набор «адресов» сервера, к которым приложение обращается. В задании — **REST API**: запросы по HTTP, данные в формате **JSON**.

```
Приложение --(POST /login, JSON)--> Сервер
Приложение <--(200, JSON с токеном)-- Сервер
```

## Как думать при решении задач

1. Разбейте задачу на мелкие шаги (декомпозиция).
2. Для каждого шага определите вход и выход.
3. Выделите повторяющиеся части в функции или классы (принцип DRY).
4. Сначала сделайте так, чтобы работало; потом так, чтобы было чисто.

::: tip
На чемпионате это же умение называется **тайм-менеджментом**: спринт идёт 20–90 минут, и вы решаете, что делать в первую очередь. Начинайте с того, что даёт больше всего баллов за меньшее время.
:::

## Подробно: переменная как подписанная коробка

Память компьютера похожа на склад с коробками. **Переменная** — коробка с наклейкой (именем), в которую можно положить значение определённого типа.

```dart
int score = 5;      // коробка «score» для целых чисел, внутри 5
score = score + 2;  // достали 5, прибавили 2, положили 7
String name = 'Аня';
```

Что важно понимать:

- Тип нужен, чтобы нельзя было положить в коробку для чисел текст: компилятор остановит вас сразу.
- Имя переменной должно объяснять содержимое: `score`, а не `a1`. Читать код будут эксперты.
- Присваивание `=` не «равно» из математики, а команда «положи справа в коробку слева».

Таблица основных типов:

| Тип | Что хранит | Пример значения | Где встретится в задании |
|---|---|---|---|
| `int` | Целые числа | `42`, `-3` | Номер хода, очки |
| `double` | Дробные | `3.14` | Размер, отступ |
| `String` | Текст | `'Привет'` | Email, название игры |
| `bool` | Да/нет | `true` | Флаг «уведомлять» |
| `DateTime` | Дата и время | `DateTime(2027,3,15)` | Время начала игры |
| `List<T>` | Список | `[1,2,3]` | Список игр |
| `Map<K,V>` | Словарь | `{'id': 1}` | Разобранный JSON |

## Подробно: условия и циклы с трассировкой

Лучший способ понять код — **трассировка**: пройти его по шагам и записывать значения.

```dart
int sumEven(List<int> numbers) {
  var total = 0;
  for (final n in numbers) {
    if (n % 2 == 0) {        // остаток от деления на 2 равен 0 — число чётное
      total = total + n;
    }
  }
  return total;
}
sumEven([1, 2, 3, 4]);
```

| Шаг | `n` | чётное? | `total` |
|---:|---:|---|---:|
| 1 | 1 | нет | 0 |
| 2 | 2 | да | 2 |
| 3 | 3 | нет | 2 |
| 4 | 4 | да | 6 |

Результат `6`. Привычка трассировать спасает при поиске ошибок в играх (проверка «пазл собран?») и в расчётах статистики (сумма баллов за неделю).

Три типа ошибок в условиях и циклах:

1. **Сломанное условие**: `>` вместо `>=`, из-за чего пограничное значение обрабатывается неверно.
2. **Бесконечный цикл**: условие никогда не становится ложным.
3. **Ошибка на единицу**: цикл идёт на один шаг меньше или больше нужного (`i <= length` вместо `i < length`).

## Подробно: функции — «мини-программы» с входом и выходом

Функция принимает **параметры** (входные данные), что-то делает и **возвращает результат**. Хорошая функция делает одну вещь и называется глаголом.

```dart
// Принимает email, возвращает true, если адрес корректен
bool isValidEmail(String value) => RegExp(r'^[a-z0-9]+@[a-z0-9]+\.[a-z]+$').hasMatch(value);
```

Почему это важно для баллов:

- Одинаковый код в двух местах нарушает **DRY**. Вынесли в функцию, вызываем из обоих мест.
- Функция, которая делает одно, проще **протестировать** и **описать комментарием** (что принимает, что возвращает) — это требование модуля А.

## Подробно: как искать ошибки (отладка)

Ошибки неизбежны. Нужен порядок действий:

1. **Прочитайте сообщение** целиком. Первая строка говорит, что произошло, ниже — где (файл и номер строки).
2. **Найдите свою строку** в стеке вызовов: ту, где указан ваш файл.
3. **Проверьте значения**: поставьте лог `AppLog.debug(...)` или `print` перед проблемным местом.
4. **Сузьте область**: закомментируйте часть кода и проверьте, исчезла ли ошибка.
5. **Используйте отладчик** Android Studio: точка останова (клик слева от номера строки) и запуск в режиме Debug. Можно смотреть значения переменных и идти по шагам.
6. **Исправьте одну вещь** и проверьте. Не меняйте пять мест сразу.

::: tip
На соревновании не тратьте больше 5–7 минут на одну ошибку. Если не получается, оставьте комментарий `// TODO`, переходите к следующей задаче и вернитесь позже. Заметку о проблеме запишите во вкладке «Симуляция».
:::

## Подробно: как устроено мобильное приложение

Приложение — это постоянный цикл «событие → реакция → перерисовка»:

1. **Событие**: пользователь коснулся кнопки, пришёл ответ от сервера, сработал таймер.
2. **Реакция**: ваш код изменил данные (`score++`), отправил запрос, сохранил токен.
3. **Перерисовка**: Flutter заново строит часть интерфейса по новым данным.

Поэтому код в приложении делится на три роли: **что показать** (UI), **что сделать** (логика), **откуда взять данные** (сервер и память). Слои архитектуры (Presentation, Domain, Data) — как раз эти три роли, аккуратно разложенные по папкам.

## Учимся: навык 1. Алгоритм и программа

**Идея.** Алгоритм живёт в голове или на бумаге, программа в файле. Сначала всегда алгоритм.

**Как научиться.** Берите любую бытовую задачу и записывайте её шагами так, чтобы её мог выполнить «робот», которому ничего нельзя додумывать.

Пример: «заварить чай».
1. Налить воду в чайник.
2. Включить чайник.
3. Если вода не закипела, подождать минуту и проверить снова.
4. Положить пакетик в кружку.
5. Залить кипятком.

Что здесь есть: **последовательность** (шаги 1, 2, 4, 5), **условие** (шаг 3 «если»), **цикл** (повторять проверку, пока не закипит). Любая программа состоит только из этих трёх кирпичиков.

**Проверка себя.** Запишите алгоритм «войти в приложение» так, чтобы в нём было и условие (пароль неверный), и повторение (до трёх попыток). Затем выполните упражнение «Алгоритм проверки пароля» ниже.

## Учимся: навык 2. Типы данных

**Идея.** Тип отвечает на вопрос «что хранится в коробке». Компьютер по-разному хранит число и текст, поэтому `'5' + '5'` даст `'55'`, а `5 + 5` даст `10`.

**Как выбирать тип.** Задайте себе вопросы по порядку:
1. Это число? Целое (`int`) или с дробью (`double`)?
2. Это да/нет? Тогда `bool`.
3. Это слова или символы? Тогда `String`.
4. Это момент времени? Тогда `DateTime`.
5. Это много однотипных значений? `List<тип>`.
6. Это пары «название → значение»? `Map<ключ, значение>`.

**Примеры из задания:** количество ходов — `int`; радиус круга — `double`; email — `String`; «уведомлять» — `bool`; время игры — `DateTime`; список игр — `List<Game>`; разобранный JSON — `Map<String, dynamic>`.

**Частая ошибка.** Телефон, номер участника, id часто хранят как `String`, даже если они состоят из цифр: с ними не считают.

## Учимся: навык 3. Условие, цикл, функция

**Условие** выбирает ветку:

```dart
if (score >= 10) {
  print('Победа');
} else {
  print('Ещё раз');
}
```

**Цикл** повторяет. `for` — когда знаем, сколько раз; `while` — пока выполняется условие.

**Функция** — именованный кусок кода с входом и выходом.

**Как решать задачу «найти сумму чётных».** Идите пошагово:
1. Что на входе? Список чисел.
2. Что на выходе? Одно число.
3. Заведите переменную для результата: `var total = 0;`.
4. Пройдите по списку циклом.
5. В цикле: если число чётное, прибавьте к `total`.
6. После цикла верните `total`.

```dart
int sumEven(List<int> numbers) {
  var total = 0;
  for (final n in numbers) {
    if (n % 2 == 0) total += n;
  }
  return total;
}
```

**Проверка.** Подставьте `[1, 2, 3, 4]` и пройдите код вручную (трассировка): ответ 6.

## Учимся: навык 4. Клиент, сервер, API, JSON

**Картинка.** Клиент — это посетитель ресторана, сервер — кухня, API — меню, JSON — блюдо на тарелке.

**Что происходит при нажатии «Войти»:**
1. Приложение собирает данные: `{"email": "a@b.ru", "password": "..."}`.
2. Отправляет запрос `POST /login` на сервер.
3. Сервер проверяет пароль.
4. Сервер отвечает **кодом** (200 — успех, 401 — неверный пароль, 500 — ошибка на сервере) и **телом** (JSON, например `{"token": "abc"}`).
5. Приложение читает ответ и показывает следующий экран или ошибку.

**Что должны уметь объяснить:**
- Зачем токен (подтверждает, что вы уже вошли, и передаётся в каждом следующем запросе).
- Почему при отсутствии интернета приложение должно показать ошибку, а не упасть.
- Чем `GET` отличается от `POST` (получить / отправить данные).
